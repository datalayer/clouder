# Scaling

The platform operator [provisions](/operations/management/) the Kubernetes cluster with the Jupyter Contents, Environments and Pools.

Based on the user traffic, the operator has to size the Kubernetes Nodepools and Jupyterpools size to balance availability and costs.

The size of the Nodepools and Jupyterpools can be updated based on the expected traffic. This is how you achieve scalability.

The API services can be scaled up to serve in parallel more traffic in needed, ensuring parrallel scalability.

Read the available [benchmarks](/benchmarks/) to get more information on the various up- and down- scaling cases.

## Scaling Up

Scaling-up is achieved by giving more nodes to the related [Nodepools](/cluster/kubernetes/labels/), e.g. `jupyter-cpu-medium`, `jupyter-cuda-medium`...
.

## Scaling Down

Scaling-down is achieved by giving less nodes to the related [Nodepools](/cluster/kubernetes/labels/), e.g. `jupyter-cpu-medium`, `jupyter-cuda-medium`...

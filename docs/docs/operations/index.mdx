# Operations

The Operations section is the day-2 runbook for platform operators running Datalayer on Kubernetes.

It maps directly to the operation domains in this folder:

1. [Management](/management/): manage Runtimes CRDs (pools, environments, contents) and Users.
2. [Observability](/operations/observability/): OTEL-first telemetry operations, health checks, and troubleshooting.
3. [Scaling](/operations/scaling/): adjust node pools and runtime capacity for traffic and cost targets.
4. [Availability](/operations/availability/): keep runtime access resilient and monitor platform status.
5. [Continuity](/operations/continuity/): backup and disaster recovery procedures.
6. [Upgrades](/operations/upgrades/): staged rollout strategy for controlled version changes.
7. [Security](/operations/security/): platform security posture and trust-center guidance.

## Recommended Operations Sequence

For a new production environment, use this order:

1. Start with [Management](/management/) to validate CRDs and runtime control objects.
2. Enable [Observability](/operations/observability/) and baseline service health.
3. Tune [Scaling](/operations/scaling/) for expected workloads.
4. Review [Availability](/operations/availability/) behavior for runtime continuity.
5. Implement [Continuity](/operations/continuity/) backups and recovery drills.
6. Execute [Upgrades](/operations/upgrades/) as staged rollouts.
7. Apply [Security](/operations/security/) controls and governance checks.

The availability of online Datalayer services can be monitored on the public [Status page](https://status.datalayer.run).

If you observe slowdown, incidents, or unexpected behavior, [contact support](/support/).

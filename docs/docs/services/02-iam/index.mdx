# ☰ 🛂 Datalayer IAM

<Stack direction="horizontal" alignItems="flex-start" padding="none" style={{marginBottom: 30}}>
  <Label color="blue">Kubernetes</Label>
  <Label color="red">REST API</Label>
</Stack>

`Datalayer IAM` service provides the Identity and Access management to Datalayer and supports a variety of Authentication and Authorisation methods. It allows to manage the following artifacts.

```
🛂 Personal and Organisation Accounts.

🧑‍🤝‍🧑 Teams.

🛡️ Authorization Policies.
```

## IAM Cases

The following diagrams describe the authentication (Authn) and authorization (Authz) in various cases.

All interactions between JupyterLab and the Datalayer services are over TLS/SSL (HTTP or WebSocket) via the Ingress.

### Authenticate from JupyterLab with Username and Password

```mermaid
sequenceDiagram title Authenticate from JupyterLab with Username and Password
    JupyterLab->>IAM: Username / Password
    activate IAM
    IAM-->>Database: Check
    Database-->>IAM: ok / nok
    break if nok
      IAM-->>JupyterLab: Return authn error
    end
    IAM->>IAM: Create JWT Token
    deactivate IAM
    IAM-->>JupyterLab: Datalayer JWT Token
```

### Authenticate from JupyterLab with a 3rd Party Token

```mermaid
sequenceDiagram title Authenticate from JupyterLab with a 3rd Party Token
    JupyterLab->>IAM: 3rd Party Token
    activate IAM
    IAM-->>3rd Party IAM: Validate 3rd Party Token
    3rd Party IAM-->>IAM: ok / nok
    break if nok
      IAM-->>JupyterLab: Return authn error
    end
    IAM->>Database: Create user based on 3rd Party Token (if needed)
    IAM->>IAM: Create JWT Token
    deactivate IAM
    IAM-->>JupyterLab: Datalayer JWT Token
```

### Access a Datalayer Runtime from JupyterLab

```mermaid
sequenceDiagram title Access a Datalayer Runtime from JupyterLab
    JupyterLab->>IAM Middleware: Request with JWT Token (and 3rd Party Token)
    activate IAM Middleware
    IAM Middleware->>IAM Middleware: Check JWT validity for Authn
    break if invalid JWT
      IAM Middleware-->>JupyterLab: Return authn error
    end
    IAM Middleware->>OpenFGA: Check Authz with OpenFGA
    OpenFGA-->>IAM Middleware: ok / nok
    break if not authorized
      IAM Middleware-->>JupyterLab: Return authz error
    end
    IAM Middleware->>IAM Middleware: Logging / Tracing
    IAM Middleware->>Service: Authenticated and Authorized Request
    break if credits information needed
      Service-->>Credits: Check Credits (3rd Party Token)
      Credits->>Credits: Authn (Secret) and Authz (OpenFGA)
      Credits-->>External Credits: Check Credits (3rd Party Token)
      External Credits-->>Credits: Credits (3rd Party Token)
      Credits-->>Service: Credits Response
    end
    Service-->>IAM Middleware: Response
    deactivate IAM Middleware
    IAM Middleware-->>JupyterLab: Response
```

### Create a Runtimes Runtime from JupyterLab

```mermaid
sequenceDiagram title Create a Runtimes Runtime from JupyterLab
    JupyterLab->>Runtimes Service: Request a Runtimes Runtime
    activate Runtimes Service
    Runtimes Service->>Runtimes Service: Check JWT validity for Authn
    Runtimes Service->>Runtimes Service: Check Authz with OpenFGA
    Runtimes Service->>Operator: Request a Runtime
    Operator->>Operator: Authn with Secret Key
    Operator->>Runtimes Runtime: Create a Runtime Pod and Ingress
    Operator-->>Runtimes Service: Response (Runtimes Token and URL)
    Runtimes Service-->>JupyterLab: Response (Runtimes Token and URL)
```

### Access a Runtimes Runtime from JupyterLab

```mermaid
sequenceDiagram title Access a Runtimes Runtime from JupyterLab
    JupyterLab->>Runtimes Runtime: Access a Runtimes Runtime (URL + Token)
    Runtimes Runtime-->>Runtimes Runtime: Check Runtimes Token
    break if token invalid
      Runtimes Runtime-->>JupyterLab: Invalid
    end
    Runtimes Runtime-->>Runtimes Runtime: Execute request
    Runtimes Runtime-->>JupyterLab: Response
```

### IAM at Ingress Level

In order to use `Datalayer IAM` as a Nginx Ingress middleware checking the user identity and authorization, the Ingress specification must have the following annotation (any service can be protected, aka forcing authentication and passing policies, using the following annotation on the Ingress).

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  annotations:
    nginx.ingress.kubernetes.io/auth-url: "http://datalayer-iam-svc.datalayer-api.svc.cluster.local:9700/api/iam/v1/auth"
    nginx.ingress.kubernetes.io/auth-snippet: |
      proxy_set_header X-Forwarded-Method $request_method;
      proxy_set_header X-Forwarded-Proto $scheme;
      proxy_set_header X-Forwarded-Host $host;
      proxy_set_header X-Forwarded-Uri $scheme://$host$request_uri;
```

# ☰ 💼 Datalayer Contents

<Stack direction="horizontal" alignItems="flex-start" padding="none" style={{marginBottom: 30}}>
  <Label color="blue">Kubernetes</Label>
  <Label color="red">REST API</Label>
</Stack>

`Datalayer Contents` owns the catalog and lifecycle of content sources used by
notebooks, agents and Code Sandboxes. It stores control-plane state in Solr,
resolves credential references through Vault and coordinates Runtimes,
Operator, Library and provider adapters. File bytes remain in managed or
provider storage; credentials never become catalog fields.

## Processes and ports

| Process | Purpose | Default port |
| --- | --- | --- |
| API | REST, OpenAPI, catalog and operation control | `9400` |
| Worker | Durable transfers, synchronization, reconciliation and cleanup | none |
| Flight gateway | Arrow Flight and Flight SQL data plane | `9401` |
| Local bridge relay | Authenticated local-folder bridge sessions | `9402` |

The chart enables the API and worker. The API serves the catalog, User Folder,
resumable Transfer, attachment-manifest and immutable Dataset-revision
contracts; the worker handles durable operations, terminal transfer
audit/provenance reconciliation, abandoned-transfer cleanup and version
retention. Flight and bridge remain
disabled until their protocol milestones are installed, and their binaries
fail closed instead of pretending to serve traffic.

## Routes and authentication boundaries

| Surface | Route | Authentication boundary |
| --- | --- | --- |
| REST API | `/api/contents/v1/*` | IAM user JWTs for user operations; scoped service identities for internal callers |
| Arrow Flight | dedicated HTTP/2 route on `9401` | Short-lived, audience-bound capability issued by the REST API |
| Local bridge | dedicated relay route on `9402` | One-session, one-sandbox bridge capability; never a stored provider credential |

`ping`, `health` and dependency-aware `ready` are Kubernetes probe surfaces.
Catalog, operation and capability endpoints are protected. Runtimes, Operator,
Library and workers use service identities with only their required scopes;
they do not forward a reusable end-user token to a sandbox. Keep Flight and
bridge listeners private until their protocol implementations and network
policies are enabled.

## Dependencies

- SolrCloud with `contents`, `content-objects`, `content-operations` and
  `content-audit` collections;
- IAM JWT and service identities;
- Vault for credential references;
- managed object storage for User Folders, Dataset revisions and staging;
- Runtimes and Operator for Datalayer Code Sandbox attachments; and
- Library for publication of selected immutable Dataset revisions.

Initialize and protect the Solr collections before enabling production writes.
See [Solr](/services/system/solr/) and
[Continuity](/operations/continuity/).

## Deploy

Build and push the current service image from the Services repository:

```bash
cd plane/etc/dockerfiles/datalayer-contents
make build-dev
make push
```

Deploy with Plane:

```bash
plane up datalayer-contents
kubectl rollout status deployment/datalayer-contents -n datalayer-api
```

The public REST ingress is `/api/contents`. Flight and bridge require their
dedicated HTTP/2/TCP routes when those processes are enabled.

### Local development

Start Contents with the same local supervisor used by the other services:

```bash
plane pf-solr
plane local --services iam,spacer,contents --logs contents
```

The API listens on `http://localhost:9400`. `plane local` exports
`DATALAYER_CONTENTS_URL=http://localhost:9400` to locally launched clients and
services, validates `/api/contents/v1/health`, prefixes its logs and terminates
the process during normal cleanup. The production client default remains
`https://prod1.datalayer.run`; set `DATALAYER_CONTENTS_URL` explicitly whenever
the service runs on a separate host.

## Verify

```bash
kubectl get pods,service,ingress -n datalayer-api -l app=contents
kubectl port-forward -n datalayer-api service/datalayer-contents-svc 9400:9400
curl http://localhost:9400/api/contents/v1/ping
curl http://localhost:9400/api/contents/v1/health
curl http://localhost:9400/api/contents/v1/ready
```

`health` reports process liveness. `ready` separately probes required Solr and
Vault dependencies and returns `503` without including credentials when a
required dependency is unavailable.

## Configuration

| Variable | Purpose |
| --- | --- |
| `DATALAYER_CONTENTS_API_PORT` | REST listener port; default `9400` |
| `DATALAYER_CONTENTS_FLIGHT_PORT` | Flight listener port; default `9401` |
| `DATALAYER_CONTENTS_BRIDGE_PORT` | Local bridge listener port; default `9402` |
| `DATALAYER_CONTENTS_REQUIRE_SOLR` | Make Solr mandatory for readiness |
| `DATALAYER_CONTENTS_REQUIRE_VAULT` | Make Vault mandatory for readiness |
| `DATALAYER_CONTENTS_DEPENDENCY_TIMEOUT_SECONDS` | Timeout for each readiness probe |
| `DATALAYER_CONTENTS_STORAGE_BACKEND` | Managed-byte backend: `local` for development or `s3` for deployed environments |
| `DATALAYER_CONTENTS_STORAGE_ROOT` | Root used by the local managed-byte backend |
| `DATALAYER_CONTENTS_STORAGE_BUCKET` | S3 bucket for User Folder versions and transfer staging |
| `DATALAYER_CONTENTS_STORAGE_ENDPOINT_URL` | Optional S3-compatible endpoint |
| `DATALAYER_CONTENTS_STORAGE_REGION` | Optional S3 region |
| `DATALAYER_CONTENTS_USER_FOLDER_QUOTA_BYTES` | Per-user User Folder byte limit reserved before upload |
| `DATALAYER_CONTENTS_USER_FOLDER_QUOTA_OBJECTS` | Per-user User Folder object limit reserved before upload |
| `DATALAYER_CONTENTS_VERSION_RETENTION_DAYS` | Retention period for superseded object versions |
| `DATALAYER_CONTENTS_CLEANUP_INTERVAL_SECONDS` | Worker cleanup/reconciliation interval |
| `DATALAYER_CONTENTS_URL` | Public/client base URL; production defaults to `https://prod1.datalayer.run`, local Plane uses `http://localhost:9400` |
| `DATALAYER_IAM_URL` | IAM endpoint used to resolve the caller's memberships |
| `DATALAYER_SPACER_URL` | Spacer endpoint used to resolve accessible spaces |
| `DATALAYER_SOLR_ZK_HOST` | ZooKeeper ensemble the Solr DAOs connect through; required by the API and the worker |
| `DATALAYER_SOLR_URL` | Internal Solr HTTP endpoint, polled by the readiness probe |
| `DATALAYER_SOLR_USERNAME` / `DATALAYER_SOLR_PASSWORD` | Solr identity, supplied through Kubernetes secrets in production |
| `DATALAYER_VAULT_URL` | Internal Vault endpoint |
| standard `DATALAYER_JWT_*` variables | IAM token verification |
| standard `OTEL_*` variables | Logs, traces and metrics export |

Do not place Vault tokens, provider credentials or signing material directly
in chart values. Use `contents.envValueFrom` and Kubernetes Secret references.

## Logs and scaling

```bash
plane logs datalayer-contents
kubectl logs -n datalayer-api -l app=contents -f
kubectl scale deployment/datalayer-contents -n datalayer-api --replicas=2
```

Scale API and worker independently. Keep Flight and bridge disabled until their
readiness and protocol implementations are available in the selected image.

## Observability

The API exports structured logs, traces and metrics through the standard
`OTEL_*` settings. Alert on failed dependency readiness, authorization and
capability-token rejection, stuck operations, reconciliation retries and
cleanup backlog. Data-plane processes additionally report transfer bytes,
Flight batches/rows and active bridge sessions once enabled. Logs and spans
must never contain JWTs, Vault values, provider credentials, signed URLs or
Flight tickets.

## Tear down

```bash
plane down datalayer-contents
```

Removing the deployment does not delete Solr collections, managed objects,
Vault credentials or Solr backups. Archive or delete content through the API
and follow the recovery/retention runbooks instead of deleting storage from
the Helm release.
